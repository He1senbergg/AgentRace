## 2. 已实现的行为

### 2.1 三种提示词，不再用一大段相互覆盖的指令

探索阶段允许下一条命令或答案；格式修复阶段给出原始错误回答和具体错误类型，要求只修控制结构；提交阶段只展示答案协议，不再给出命令选项。

仍保留英文主模板，以免把语言切换和状态机改造混成一次无法归因的实验。本轮没有证据证明中文模板或英文模板哪一个对赛事模型更准。

内部 `answer` 仍必须是字符串。题目要求 JSON 时，需要把题目 JSON 序列化进这个字符串。程序不会把对象、散文、数组等任意“猜成答案”。只允许去掉包住**整份回答**的一层完整 Markdown 围栏，之后仍严格检查完整 JSON；不从任意文本中截取第一对大括号，不使用 `eval`。

重复键、非法 Unicode、NaN/Infinity、双重主动作、未知字段、错误类型仍拒绝。修复请求带稳定错误码及至多 6,000 字符的原回答；裁切有明确标记。

### 2.2 工具结果成为候选答案的两条明确路径

这是**内部模型回答协议**，不是新增比赛 API 字段。程序对外仍只发送 `roleCommandMap / prompt / executeCmd`。

路径 A：模型明确声明下一条命令只输出符合本题格式的最终或部分答案：

```json
{"command":"python3 solve.py","answer_from_stdout":true}
```

命令结果在连续的下一回合到达、退出码为 0、结果完整且非空时，程序可以直接提交 stdout，省去再调用模型抄答案的一轮。文档发现、调试日志或混合输出不应使用这个标记。没有标记的普通命令结果不会自动提交。

路径 B：继续探索时，明确保存以前某个成功结果：

```json
{"command":"python3 inspect_remaining.py","candidate_answer":"Beijing","candidate_source_round":3}
```

`3` 指**收到工具结果的回合**，不是发出命令的回合。候选必须等于该回合完整 stdout，或与整份 stdout 的严格 JSON 值等价。不能仅匹配输出中的某个单词，也不能把日志里任意一行或 `skill` 里的散文当作候选。程序保存最多 8 个近期成功来源；超出保留范围的来源不能用于创建新候选。

接近截止、模型仍给命令或格式错误时，程序可提交已保存且未被重复提交规则阻止的候选。失败输出、超时输出、截断输出、迟到或跨任务结果均不能授权自动提交。工具结果沿用原 16,384 字符本地完整性门槛；超出时不自动兜底，但直接模型答案仍保持原始字符串、不静默截断。

**来源匹配只证明答案来自哪份工具输出，不证明题目答对。**本程序不能通用验证任意任务的字段含义或真值。没有候选时仍可能超时不交卷；不会为了降低这个指标编造答案。

### 2.3 回合与重复操作约束

保留原异步时序：发送 prompt → 下一回合接收回答；执行命令 → 下一回合接收结果。最后一条普通探索命令仍必须给结果、答案和反馈留出回合。未知截止时间不会凭空猜测。

任务结束、任务正文变化、主人死亡/离开任务点时不会沿用旧候选。缺失回合时不消费未能关联的旧响应，并清空自动兜底来源；仅保留标注的过程提示。官方没有任务实例 ID，因此未观测到空窗的同描述换题仍是未解决的识别边界。

相同命令出现权限/找不到命令类返回 126/127 后，不会在没有新成功观察时原样重发；其他失败允许一次额外重试，之后要求改变操作或证据。成功但没有 stdout 的环境修复命令可以解除重试阻断，但不能变成答案。

重复答案在没有新成功观察时被拦截。明确的动作非法反馈允许一次重发；动作合法或任务结束均不等于答题正确。错误码 2 保留“错误或部分正确”的含义，不当作零分或完全失败。

### 2.4 上下文与方法提示

当前工具观察、稳定任务文档和历史观察分区，当前观察在生成 prompt **之后**才写入历史，因此不会当轮复制两遍。自动文档发现只在 `task_documents` 中保留正文。

完整任务原文不静默裁切。辅助上下文的序列化预算为 36,000 **字符**，优先删除历史经验和较旧观察，再缩减大块材料，并显示省略标记。这不是模型 token 上限，也不保证任何长度的任务都能装进赛事模型窗口。普通长输出仍可能失去中间内容；本轮未实现通用语义压缩或任意题目的字段抽取器。

候选答案和 `skill` 分开保存。`skill` 现在只要求可复用方法，旧经验按题目词项/任务文档相关性筛选，不再直接发送上题命令及原始观察。所有方法提示仍标“正确性未验证”；这不是经过判题器认证的技能库，也不能保证模型写入的自然语言方法没有夹带旧数值。

## 4. 替换与启动

优先保留当前仓库备份。覆盖补丁针对上述 ZIP 基线；若本地已经有之后的新修改，先检查差异，不能假定可无条件覆盖。

将补丁的 `src/`、`tests/`、`tools/`、`docs/` 等按同名目录合并到仓库根。不要删除原来的 `.git`、`.venv` 或本地配置。**不能只替换 `main3.py`**：本轮生产改动是四个包内文件。也可以把完整包解压到新目录，使用现有 Python 虚拟环境运行。

沿用原启动方式和端口，例如：

```bash
python src/main3.py 8080
```

第一条完整测试命令检查整个仓库；上面的启动命令使用 8080 端口，实际比赛保持你原来使用的端口。Windows 可使用原 `.venv\Scripts\python.exe`，Linux 仍可使用原 `run.sh`。没有新增第三方依赖，也没有改比赛请求/响应接口。

## 5. 可选原文审计：默认关闭

普通日志增加 `prompt_version / prompt_stage / protocol_error / candidate_available / submit_mode / dedup_block / context_omissions` 等元数据，但不打印题目、prompt、回答和沙盒命令。

只有确认赛事和公司允许把这些内部材料保存在本机私有目录时，才设置 `AGENTRACE_TASK_TRACE_DIR`。它会保存原始输入与输出，**不自动脱敏，可能包含内部文档或凭证**；不要上传公开仓库，不要把它当普通日志随意转发。

PowerShell 示例：

```powershell
$env:AGENTRACE_TASK_TRACE_DIR = Join-Path (Get-Location) '.private_task_traces'
python src/main3.py 8080
```

关闭：

```powershell
Remove-Item Env:AGENTRACE_TASK_TRACE_DIR -ErrorAction SilentlyContinue
```

Linux 单次启动示例：

```bash
AGENTRACE_TASK_TRACE_DIR="$PWD/.private_task_traces" python src/main3.py 8080
```

本地文件后缀为 `.tasktrace.jsonl`，单文件约 16 MiB，上限 4 段轮转；单条超过 2 MiB 时保留明确的省略元数据而不是残缺 JSON。轮转可能移除旧记录，不保证保存整场所有原文。`.gitignore` 已忽略默认目录及这个文件后缀（含轮转文件）。POSIX 下新文件权限为 0600；Windows 应使用合适的目录访问权限。

写入异常不会使已提交游戏响应失效，但异常隔离不能保证阻塞磁盘操作满足 callback 硬时限；不要在网络盘或可能卡住的文件系统上开启。重复回合请求走缓存，不重复记录原文。

## 6. 下一轮真正要观察的指标

确认模型是否遵守分阶段协议、是否会使用可选 stdout 契约、每题在截止前是否有合法提交，以及字段得分与完成回合是否改善。修复机械性缺陷不等于真实模型变聪明。没有经过赛事模型对照测试之前，不把本地解析率、来源匹配率或回放通过当作实机得分提升。
