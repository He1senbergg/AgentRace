# AgentRace V3.1：DeepSeek 版本调度修复与验证

日期：2026-09-14。版本标识：`v3.1-reviewed-fix`。
基线是用户上传的 `AgentRace-main-DeepSeek修复版.zip`，不是远程仓库的推测版本。本次直接修改源码并执行测试；没有 Git 提交或推送。

## 1. 结论与变更范围

上一轮八项审查断言由 **3 通过、5 失败** 变为 **8 项全部通过**。完整套件由 351 项增加到 **383 项**，最终代码与干净覆盖副本均 **383 项通过、0 失败、0 错误、0 跳过**。

生产文件仅改变 `src/agentrace/survival.py`（调度逻辑）和 `src/main3.py`（启动版本标识）。没有修改协议、动作校验器、HTTP 接口、任务 R1/R2、武器伤害预测、布局生成、依赖或 `run.sh`。测试和文档随包交付；既有测试数量没有减少。

这说明本地复现的缺陷已修复，不说明已经赢得正式对局。当前包没有官方裁判引擎，没有新的平台比赛分数，也没有真实任务判分。

## 2. 资源预留与满背包恢复

原补丁把“不要卖建墙石头”实现成“建墙工不能卖任何矿物”。修复后只保护实际预留石料，铜、铁及超过当前批次/剩余墙需求的石头可以出售。清理背包时保留 wall 任务；只有动作被接受才更新销售状态。

新增 `wall_reservations`，独立于临时 `job.kind` 保存批次需求上限，防止服务/补药等临时任务让建筑材料突然变成可出售资源。实际受保护数量取“观察背包石头、批次上限、剩余墙成本”三者最小值。人物死亡或当前墙目标完成后释放。日志中的 reservation 值是批次上限，不是额外拥有的石头。

持有建筑石料、施工暂缓时，不通过 income 改写建筑任务。没有石料且暂不能采石时仍允许临时赚钱，保留原建墙任务，不把修复变成“空包工人永久站着”。本轮曾发现第一稿限制过宽，先保留失败测试再收窄；记录见 `validation_v31/empty_builder_before.log`。

连续证据：从第 131 回合开始，一个没有手工预设任务、满背包 100 铜矿的工人，经真实 GameSession + 独立 DayEngine 执行 260 步。

| 指标 | 上传的 DeepSeek 版 | V3.1 |
|---|---:|---:|
| 首次出售铜矿 | 无 | 第 131 回合 |
| 最后仍持有的铜矿 | 100 | 0 |
| 260 步后墙数 | 0 | 14 |
| 独立模拟器拒绝动作 | 0 | 0 |

另测了 8 石 + 92 铜的混合满包、铁矿出售、20 石保留 8 石只卖 12 石、目标已完成、人物死亡和售矿被拒等边界。

实现位置：`survival.py:553`、`:573`、`:608`。

## 3. 已购券交付不再使炮手日落离岗

“已经付钱”不等于“可以无条件占用夜间防御时间”。交付现在检查当前动态可执行路线，并计算：移动回合 + 使用一回合 + 返回指定防御位置的回合。去掉的是采购用的额外安全余量，不是全部截止约束。

第 70 回合已经就位、能原地用券的人可以使用；需要远行升级普通墙的人不能离开炮位。不可达或来不及的旧目标不会遮住其他合法候选。目标只在动作被校验接受后占用。

两回合证据：第 70 回合携墙券工人保持 `(8,23)`；执行状态转移后，第 71 回合对相同高血目标从旧版的 2 炮恢复为 3 炮。另做跨夜延后场景，券保留并在后续白天实际完成升级，没有以“拒绝了这回合”冒充交付完成。

实现位置：`survival.py:388`、`:401`。

## 4. 夜间普通维护让位开火，保留基地救急

普通武器升级/普通墙维护仍放在火力之后，只使用空闲角色。恢复一条明确的基地救急例外：基地为 1/2 级且血量低于最大血量的 65%，存在相邻、空闲、持匹配基地券的角色时，先执行一次基地升级。优先选能保留更多可开火武器的角色，不在夜间外派远处持券人。

65% 沿用原来的紧急采购阈值，是策略参数而非官方规则。依据仓内 `AI Spec/未来战争_v1.0_比赛全貌_开发整合版.md` §23，建筑升级恢复满血。测试验证指令、控制者占用和剩余开火，并未模拟机器人选谁攻击或声称该场景一定免死。

基地 1 HP 的反例现在是 **1 次基地升级 + 2 炮开火**；健康基地和普通双武器券场景保持 **3 炮开火，不用普通券抢角色**。另测了二级基地、错误券、冷却窗口中优先空闲角色。

实现位置：`survival.py:443`、`:662`。

## 5. 已开火/已升级目标过滤与失败后的替代候选

持券交付排除 `v.modified` 中的建筑；开火匹配也排除已修改/已经占用的武器。候选被拒绝后继续尝试其他合法目标，而不是直接结束整个交付流程。失败动作不空占目标、不改写任务。

合法冷却场景中，两门炮开火，剩余工人给第三门冷却炮升级，不再因先选中已开火炮而空闲。诊断事件保留 `action_rejected`，避免随后“已在炮位”的记录覆盖失败线索；同时增加 `delivery_deferred`、`base_rescue`、`wall_funding`。

## 6. 纠正测试而非放宽验收

原“建墙工卖铜也必须失败”的断言改为“铜可卖、石头与任务保留”。原夜战用例中两炮与基地重叠的问题已纠正，现在建筑和人物无重叠、三个炮手可匹配、有足够目标 HP，开火断言从至少两炮加强为三炮。原第 68 回合用券用例的人物与炮重叠也已纠正。

32 项新增回归在 `tests/test_survival_v31.py`。原八项独立审查保留在 `validation_v31/reproduction/test_review_regressions.py`，最终全部通过。

## 8. 复现与部署

使用正常运行比赛的 Python/Flask 环境，在仓库根目录执行：

```bash
python -B -m unittest discover -s tests -v
python -B tools/validate_survival_v31.py --output-dir local_validation_v31
```

第一条是完整测试；第二条会再次跑完整测试及全部六阶段验证，并保存每个命令的原始输出、退出状态和源码哈希。JSON 中的 /mnt/data 路径只是本次执行环境记录，不要求用户照抄该路径。

推荐将覆盖补丁解压到现有仓库根目录，使 src/tests/tools/docs 与现有目录对应，保留原 .venv 和 .git。先备份并停止旧进程，覆盖后用原命令、原环境、原端口重新启动。不要只替换入口，不要把补丁解压到 src 内。

启动日志：`[main] strategy_mode=survival; survival policy=v3.1-reviewed-fix`。必须确认前半段是 survival；残留的 `AGENTRACE_STRATEGY=defense` 会启用旧模式。完整包不附带 .venv 或 .git，另开目录运行时需继续使用已有解释器。

## 9. 剩余边界

本轮没有重做炮位布局：最后一门炮的唯一服务邻格被队友长期占据时，通用让位/重布局仍未证明解决。新的动态候选过滤能换目标，但不等于解决所有瓶颈。墙体真实挡路价值、官方机器人行动/伤害、任务正确率及实战生存长度，仍需本版平台新日志验证。

当前结论是本地已复现的四类调度问题修复完成，既有首日基准未退化；不是整场比赛策略已获胜的认证。
