## 3. 对六个思路的实现与取舍

### 3.1 全部三炮后置，但不做三个紧挨着的炮位

基地左侧示例：基地锚点 `(9,22)`，新炮位 `(8,23)`、`(8,21)`、`(8,20)`。右侧根据本方基地位置作180度镜像：`(32,8)`、`(32,10)`、`(32,11)`，不根据文件名或红蓝颜色硬编码。

后排保留一个内部操作空位，不再把第三炮放在面向机器人一侧。新开局按新位置建设；观测中已存在的三座炮不会为了套新布局被拆掉。丢炮后新建才使用后排空位。

规则规定火箭不被中间建筑挡住。静态射程检验中，正面机器人位于前墙外一列时，旧前炮处于3格潜在攻击半径内，新三炮均不在该半径内；新一级火箭的10格射程仍覆盖这列全部正面位置。这是几何覆盖检验，不是私有机器人选目标算法的仿真。

代价：更远处的机器人可能比旧前炮更晚进入一级/二级炮射程，且实际炮手回防仍需检查。本次独立经济模拟的16个V3.8场景，入夜均有3名实际可配对炮手。

### 3.2 把六堵正面墙的最低等级当成有截止时间的建设工程

目标从“有剩钱才升级”改为：核心火力成立后，第三天优先补3堵二级前墙，第四天及以后补齐6堵。核心火力至少是三座炮中有一座三级、至少两座达到二级，或历史已经观察到两座三级炮。

最高日维护额度变为：第一天0、第二天20、第三天80、第四天以后140金币；核心火力未成立时仍限制到20。额度含实际维护支出和当回合预留，不是额外发钱。第三天三堵升级约60金币，第四天从零补六堵约120金币，剩余额度供有限维修。完成最低配置后，侧后墙仍保持一级，不无限挤占炮台资金。

优先级不是“所有墙先于所有炮”。第一座全屏三级炮、第二座炮升二级、紧急基地升级仍受保护；第四天的六堵前墙最低配置可以排在第二座炮继续升三级之前。此处是明确的防守取舍，实机必须同时观察击杀速度和墙体寿命。

运输也改了：一个真实携券者单批最多带3张前墙升级券，逐堵走到位置再使用。购买前同时检查金币、个人背包、已持有券、日预算、采购—配送—回防的完整路径；买券不等于升级已完成。430回合是复盘检查点，不是盲目写死的统一召回时刻；第四天从白天开始就可安排这项工程，461入夜前仍受真实时间预算约束。

### 3.3 夜间敌方压力：先守住，再有限试探

对己方：连续观测中建筑掉血，而上回合附近4格没有可解释的机器人时，记录 `unexplained_structure_damage`。它表示“来源未能解释”，不等于认定对方攻击。之后12回合暂停“清完本方机器人就集体外出”的夜间工作释放，持续掉血会刷新窗口。

对敌方：只有本方机器人已确认清完、基地至少80%血、六堵正面墙都在且至少60%血、至少两座三级炮、实际仍有空闲且健康炮手时，才允许一座三级火箭试打一轮敌方可见前墙。优先已有较弱目标；残局可打低血基地。防守、任务、救基地、已有配送动作都不会被它抢走。

每回合最多一轮；发射回合、武器、目标及下一帧伤害观测都记录。连续3次没有确认的伤害观测就停止继续尝试。不把空数组之外的异常机器人字段、首个刷怪回合当成安全清场；不忽略接口给出的射程或冷却。

**没有复刻对手“还剩少量机器人就分火力拆墙”的激进时机。** 当前先做确认清场后的低成本试探。敌方HP下降也可能来自其本方机器人，反馈字段明确 `causal_claim=false`。没有官方完整战斗结算器，不能以本地假设的PvP伤害宣称此策略已提高胜率。

### 3.4 基地升级是保险，不再满血自动用

两级券统一处理：普通情况下，一级基地在750/1500、二级基地在1500/3000触发。

```text
触发血线 = min(90%最大血量,
               max(50%最大血量,
                   (携券者预计到位步数 + 2) × 伤害风险估计 + 15%最大血量))
```

伤害风险估计取连续观测的实际掉血趋势与贴近基地的机器人潜在攻击量中的较大值；它不是预测到的确定伤害。跨帧缺口不推断掉血速率，升级改级不当作掉血。满血始终不触发。

券必须真的在某个存活角色背包中；任务忙碌角色不能被抢用。最近真实通路不通时单列阻塞持券者，不再把“找不到路”错误显示为0步。紧急使用最多允许3步实际接近；通道被自家炮手挡住时先让阻挡者走到安全空位，等下一帧确认，再让持券者前进、使用。该三步状态变化已由独立引擎逐步执行验证。

满血时持券不是无偿增加血量：买券依然花100/150金币、占库存，且存在携券者死亡、突发集火和同回合结算顺序风险。因此不等残血1点，也不宣称阈值永远来得及。

### 3.5 偏矿开局：做降级处理，但不能修复地图分配

依据实际矿点、可走路径、回防成本、自己已成功采集的数量重算矿点收益；两工人选择同一矿点时施加折扣，避免无条件扎堆。不能观测到的对手采矿量不伪装成已知库存。矿点消失或日志中断会清掉不可靠的旧采集估计。

石料四份完整访问成本超过36回合，或没有可达石料时，第一天墙目标由10降至6，远程石料批量由8降至4；仍只让一名工人主建墙，另一名保留采销现金流。它不会为补墙放松入夜回防约束，也不会假定下一次随机矿点一定刷在己方。

**极端偏矿模拟没有证明改善。** 把仅有的三个矿点全部移到另一侧的四组对照中，新旧版第一天矿物收入都是5金币；V3.8仅建1堵墙，旧版为1–2堵。正常四张起点地图的新版本首日现金也有下降（60/65/65/60，对照61/80/77/90），不能把“更会估计资源”直接说成“收入提高”。当前主要收益证据来自墙体工程和基地券，而不是地图不公平已被解决。

### 3.6 富裕时扩围：18墙双通道，不是20墙封死

最终保留普通14墙C形；只有第四天及以后白天、三炮全三级且各至少85%血、六堵正面墙至少二级且各至少80%血、三名角色各至少80%血、基地至少75%血、已观测可用金币扣当前资本预留仍至少250、至少20回合工作窗口、无本方机器人和近期不明远程掉血时，才扩到18墙。

为何不是19或20：20墙封死会失去出入通路。19墙单出口虽然通过静态连通和三操作位匹配，但70回合状态模拟发现回防拥堵，入夜只剩1名实际炮手到位；因此这版方案被淘汰。18墙双通道用相同起点与经济引擎重跑，新增四堵墙在391/392/395/399落地，461观测时3名炮手均实际到位。

主出口 `(7,22)`、服务口 `(7,20)` 永远不在墙目标中；右侧镜像为 `(33,9)`、`(33,11)`。每次真正放墙仍检查路径、占用、工人可外出与三炮独立操作位置。富裕条件失效就停止进一步扩建，不拆已建好的墙。
