# V3.5操作说明

## 参赛只做这几步

1. 沿用原来可用的上传流程，用此次 CoreGeek.tar.gz 替换旧参赛包。
   包内只有 CoreGeek/main3.py，已经完整，不需从旧包拷贝其他文件。
2. 检查平台启动print中有 build=v3.5-clearwave-capital，
   survival policy=v3.5-firepower-before-maintenance。
3. 先做一次同对手、同设置的红蓝交换，保留双方分数和平台导出的完整print日志。
   不删REPLAY3行，不进入运行容器，不设置环境变量，不需要本地启动。
4. 仓库同步：覆盖补丁解压到已有仓库根目录，替换src/main3.py、CoreGeek/main3.py、
   CoreGeek.tar.gz、tools/build_single_file.py及标注的当前README/文档。
   不额外套一层仓库目录。提交前留存V3.4用于回滚；不要求Git push或Codex重写。

单文件入口的命令仍由平台执行：python main3.py <平台传入的端口>。
源码中的task_*.md、spec.md等是游戏沙盒任务材料，不是提交依赖。

## 观察项

清场后应出现 mode=NIGHT_WORK，且有collect、move、buy、sell等合法工作动作；
有本方机器人时恢复NIGHT防守。wall_budget记录等级上限和当日维护余额，
capital_goal/capital_reservations记录采购目标与预留，weapon_levels记录实际等级。
目标是升级真正落地并延长基地生存，不是只出现某个日志标记。
任务技能仍为deployment_crlf_v34/heritage_cursor_v34，表示保留已验证执行器，
不是误启动旧版本；以main的V3.5标识为准。
