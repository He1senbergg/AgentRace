# AgentRace 当前检查点：Survival V3 + 裁判复核修复

日期：2026-09-14。在 V3 candidate（commit `be44da3`）之上做了一轮独立裁判复核（judge pass），修正三个经复现确认的调度缺陷。基线仍为本地上传包，未拉远程仓库、未自动提交。

## 裁判复核结论（2026-09-14）

独立复核方式：通读 `AI Spec/` 与 `docs/`、全部 344 项既有测试、600 步随机观察持续会话模糊测试（无异常、无非法动作）、4 张初始地图×两种资金首日对照、1300 步×两个起点的经济连续性、Round5/6/7 日志审计。协议与动作合法性层在此范围内没有任何非法动作或异常；三个已确认并修复的行为缺陷全部在 V3 `SurvivalPlanner` 调度层：

| 缺陷 | 复现证据 | 修复 |
|---|---|---|
| 建墙工携带的石头会被 `sell()` 清算 | `sell()` 直接把 `jobs[kind]` 改写为 `sell`，把 8 块石头批量当矿卖掉，销毁整批墙面 | `sell()` 在 `wall` 任务进行中且墙数未达标时拒绝出售石头 |
| 夜晚 `held_delivery` 先于开火执行，把控制者回合耗在升级券上 | 3 炮+3 控制者全 ready 且有目标时只开 1 炮、另 1 控制者去 `use` 券 | 券/修复品延迟到开火之后、仅未开火控制者执行；ready 且有效目标的炮优先开火 |
| 已购入的券在日间 margin 不足时被放弃，工人被 `income` 拽去卖矿，券永久卡死 | origin=0 的 1300 步经济连续性在 R1180 后卡死、986 金币滞留、最后一门炮停留 L2 | `held_delivery` 日间只要求目标可达，不再用 margin=2 的往返预算卡券 |

另发现并记录、**未当作本轮修复范围**的深层风险：

- 紧凑炮位布局可能把三门武器之一塞进只有 1 个空闲邻格的口袋；该格若被他人返位格占用，则该炮永久无法升级/维修（观察到的卡死根因）。完整解决需要重掷炮位布局，本轮不冒时序回归风险。
- 墙建工仍可能被 `income()` 指派采矿任务打断批次（未出售石头，批次不丢石头）；这是一项已记录的剩余风险。
