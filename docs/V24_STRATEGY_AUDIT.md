证据分类：

- **FACT**：明确规则、直接日志观测或已阅读的代码行为。代码事实不等于战略收益事实。
- **INFERENCE**：证据支持的解释，但仍有替代原因或未知结算环节。
- **HYPOTHESIS**：需要干预实验验证的策略命题。

### 0.1 从比赛目标定义价值

AI Spec §38～41：任务产生分数和金币；击杀按类型计分；生存十天可得550分；基地不同回合被毁时，先毁者直接判负。用户要求的优先顺序据此采用：station生存 → 得分及有效杀伤 → 减少持续漏防 → 在剩余 gold、actor-turn、位置和时间约束下增加下一阶段生存余量。得分目标不能只经由 leakage 解释：任务失败会直接损失得分，也会经由金币减少影响防守。

候选因果闭环：

```text
真实收入 + 已有库存 + 可用角色 + 地图 + 剩余白天
  → 提出任务 → 预算/分工 → 行走/采购/建设/交付 → 实际资产/站位
  → 可用攻击窗口 × 可命中覆盖 × 目标分配 → 有效伤害/及时击杀
  → 敌人剩余HP、路径与存活时间 → station/炮手受损
  → 次日存活、恢复成本、生产能力、可得分时间 → 最终胜负
```

墙不是可以直接加到基地上的HP；gold不是已交付防御；三座武器不是三路随时可用火力；发出attack不是一次确认击杀。生存余量应暂记为 `station当前HP − 下一时间窗预计不可避免伤害` 的区间估计，附炮手可用性和不确定性，不能再用墙总HP替代。

## 3. Round6 Leakage Analysis

### 3.1 三种不同的“漏防”必须分开

1. **几何突破**：敌人已进入墙圈以内；需要坐标证明，不要求已经造成伤害。
2. **威胁漏出**：仍活着的敌人已到达可能攻击station/炮手的范围，未被及时处理；即便在墙外也可能出现。
3. **已实现损伤**：连续观测station或角色HP下降。它不能单独指出敌人ID、路径、攻击目标或击中时刻。

AI Spec §27给出所有机器人攻击距离3，行为仅写“攻击阻挡移动的单位”；没有给出完整寻路、选目标、机器人攻击是否受墙遮挡、攻击频率和station多格取距实现。因而不能断言“机器人一定绕后”“攻击必能穿墙”或“建满环即可免疫”。

### 4.5 PRE_NIGHT、RETURN及deadline

当前直接回位门禁为 `r > D − 5 − direct_return_cost + 1`，不是全队固定Rxx停工；满足门禁的actor改RETURN，plan可标PRE_NIGHT，其他人仍可工作。资本和下一墙又各有完整行程门禁。原Round5 G17 R28进入RETURN后长期不重分配、R37有144G仍无owner的旧失败已在当前代码被重新评估机制替换，不能称其在Round6原样复现。

但仍存在三类问题：

1. **不可完成既有job后无替代动作**。G23 R50/L260，三人活着、62G全free、DAY_NORMAL，两worker BUILD_WALL/PAUSED，先锋LOGISTICS，actual空。R50～58连续九轮全队无命令。墙工在`execute_job`返回后不会尝试可中断经济/其他服务。这证明gold、actor、时间可以同时存在却没有转成任何动作，不证明当时存在安全有效的新防御任务。
2. **截止不一定过早**。G23 R50抽样地图/L222及角色快照/L221显示石矿最近在 `(1,9)`，两worker `(6,18)/(10,19)`、空包。用当前地图静态BFS独立计算“采1石→当前目标墙→既定slot”：移动/采集/移动/建造/回位分别 `8+1+9+1+3=22` 和 `9+1+9+1+1=21`，加5余量为27/26，对R50～70含当轮的21轮窗口确实不符现行门禁。该分析未模拟其他worker预留、动态碰撞与矿刷新；只是快照上的局部路线核对。第二条去掉余量理论上可卡最后一轮，不能据此宣布安全可行或全程最优。

### 4.6 经济与任务模型的额外边界

`EconomyPlanner.workers`优化价格×batch/(采集+运输+售出)，保留达到最佳80%的旧矿；batch、日落门禁和动态矿刷新影响可兑现收入，但分母不含买券/运券/防守价值。`TaskPlanner`按路程选任务、最坏timeout保守回位，没有用预期通过率×金币/速度奖励排序。defense模式也没有运行NewsPlanner来持续填充新闻事件，虽保留相关记忆类型。它们均说明不能预设“V2.3总体架构已足够，只需继续调数字”。

### 5.3 目标选择和覆盖的实现审计

- `DefensePlanner.attack_plan:337`按每个候选的预计有效伤害打分：敌人距任一角色≤3乘3；否则距station**锚点**≤4乘2；其余乘1。基地footprint的最近距离没有参与此权重。既无敌人攻击力、到达时限、当前目标、剩余夜长，也无击杀积分项。
- 存在overkill抑制：`min(remaining_hp, damage)`，同炮逐发、后续炮共享预测remaining；多弹可重复中心形成focus fire。但是按角色job顺序执行、逐发贪心，不联合比较各炮射程、冷却和替代目标。得分为0时为满足弹数补重复中心，也可能发出零边际价值弹，日志未记录其预计浪费。
- 20点伤害打未致死的高HP目标与及时打死20HP致命目标，如果空间权重相同，可能同分；没有明确奖励“让下一轮station少承受一次攻击”。角色附近×3也可能压过直接station危险×2，这是待测风险，不是已从Round6证实的错靶事件。
- 物理覆盖、ready匹配、存在正收益目标分别计算；G24 R222～224说明当前两角色物理匹配到两冷却炮后，不会因第三炮ready重新定位。该炮未射的“缺邻接控制员”可确认，机器人仍有21等全图计数，但是否有可命中本队威胁还须逐敌输入。
- defense的CONTROL已邻接炮便驻守，不调用legacy的`position_controllers`冷却期邻格exposure规避，也不调用`support`的Bomb/Dizzy使用路径。规则允许的夜间非build服务并未全面进入该策略。保留工程合法性与控制员互斥，不等于这些政策选择已优化。

**结论：三rocket、2,1,1、当前scorer和驻守行为均须重新验证。现在没有证据足以选择新的最优组合，本轮不修改选型。**

## 6. Threat Model：候选评估框架（只设计）

### 6.1 状态表示与可信度

对敌人i保存观测ID、类型、HP、位置、targetTeam、dizzy、最近连续位置；对station使用四格footprint；对墙保存格子/当前HP/等级，对武器保存位置/range/cooldown/可用控制员及可达控制格。不存在的字段保持unknown，尤其 `targetTeam`只标阵营，**不表示enemy当前具体target**。

对每个敌人计算：

- `d_station`：至footprint的最短Chebyshev距离；`d_wall/contact_sector`：到实际墙及缺口/威胁方向距离。
- `breach_state`：外圈、可攻击范围内、内圈已突破；不要把进入range和穿越墙混为一事。
- `ETA_attack_station`、`ETA_contact_defense`：给区间。几何下界可用 `max(0,d_station−enemy_range)/speed_upper`；速度上界若无规则/连续观测支持则标unknown。路径估计加障碍/被墙延迟，但未知目标规则下不把BFS路径当事实。
- `q_i(u)`：第u个未来窗口攻击station的可能性/上下界，区分观测、假设、校准状态；不能把附近敌人全算在同一目标上造成重复伤害。
- `remaining_night`：剩余夜长截断未来伤害；接近天亮未杀高HP敌人可能不如立即打掉低HP近身敌人有价值。

### 6.2 威胁价值与可执行杀伤

候选未处理损失：

`L_i(H) = Σ(u=0..H) q_i(u) × possible_attack_i(u) × damage_i`

H取短作战窗口及本夜剩余时间；机器人cadence、选目标/遮挡未知时使用上下界，不输出伪精确概率。另估炮手损失引发的未来火力下降，使保护炮手和保护基地有可比较的因果价值，不再靠固定3与2表达。

对武器w/敌人i计算：合法目标、控制员可用、命中区间、每枚/每次伤害、所需攻击次数 `ceil(HP/单次有效伤害)`，以及考虑当前cooldown/移动到控制位/射程进入时间后的 `TTK_i`。AoE、railgun余能分配、gatling拦截与多弹限制必须纳入，不能把等级当作固定独立单目标伤害。

核心比较应是“本轮动作相对不执行，可减少多少未来损失”：

`ΔL(action_set) = L(no_action) − L(action_set)`

先约束station在保守短期预测中不过致死线，再比较ΔL、及时击杀/得分、控制员风险与资源成本。不能用一个大伤害加权和掩盖“未杀死会立刻打爆station”的敌人。

### 6.3 focus fire、overkill和跨炮合作

对最多三炮枚举有界候选组合，而非每炮独立挑最近者：

- 若两炮合作能在敌人第一次有效攻击前击杀，而分火不能，focus fire有时间收益。
- 若一炮已足够击杀，另一炮转向次威胁；预测damage ledger不能当平台已经杀死。对于同回合致死敌人的行为，用两种结算假设给损失区间。
- `overkill = 原始计划命中伤害 − 可消耗HP`；rocket同时记录零边际弹、低价值溅射和多个有效目标。不能把所有大AoE伤害视作同等防守价值。
- 区分“现在打一个低优先级敌人会锁住下一关键窗口”与“等待会白白损失射击次数”；只有明确未来威胁时才考虑等待/错峰，不能默认保留冷却总优。
- 无法及时杀死时评估眩晕、炮手换位、使用已有修复/升级物品等合法响应的机会成本；没有能力/库存就不能生成假动作。

### 6.4 昼夜衔接

候选白天任务的价值为“交付后预计减少下一夜的损失或提高得分”，成本向量为 `(gold, actor-turn, 位置风险, 最晚交付回合)`。任务完成必须分资产验收与防御验收；reservation只标资金状态，不提前计入survival margin。模型先离线旁路校准，再决定是否改变authority；本阶段没有实现该框架或指定权重。

## 8. V2.4 Experiment Candidates

共五个候选，均未实施。先规定实验单位为同一地图/种子、同一侧、同一敌方/波次、同一版本的一次半场或冻结夜初状态。若平台不支持固定种子/状态，不把多局简单均值宣称因果结果：分侧分层、重复并保存全部前置状态，结果标探索性。离线战斗模型未验证的机制必须做敏感性区间，不能用构造模拟替代实机。

所有行为实验以station生存为首要硬门槛，同时报告逐轮HP面积、首次损伤/突破时间、近station敌人存活HP-turn、有效击杀/得分、控制员失效窗口、金币与actor-turn成本。HP面积需同时报告station等级/升级成本，防止升级后容量不同混淆。不得仅凭八墙或总墙HP通过实验。阈值在观察结果前冻结；若样本不足则结论为不确定。

### E1. 不改策略的因果可观测基线

- **Hypothesis**：补齐逐敌状态、动作原因和资源链，可以把当前主要station损伤窗口分成可验证机制，并保持决策行为不变。
- **Evidence**：已有G21内圈地图、G24冷却/缺炮手、G22先锋FUNDING，尚不能连接逐敌伤害/替代行动。
- **Single main variable**：观测记录开/关；所有策略动作逻辑保持相同。
- **Control variables**：源码策略段、配置、默认模式、同一请求序列、随机源、任务通道、预算、布局、选型、deadline。
- **Required code changes**：下一阶段新增隔离的白名单战斗/资源链日志、逐轮输入摘要或可重放快照和离线分析器；添加响应/决策状态等价及日志性能检查。不得顺便修G22分工、换枪、改墙或scorer。
- **Metrics**：关键战斗/资本链字段完整率；带阶段原因的无fire/idle比例；输入→命令→反馈→HP delta可关联率；未知伤害归因比例；Response/决策状态差异；p95/p99及最坏耗时/日志量。
- **Success criteria**：同请求逐轮Response和决策状态零差异；新增故障不影响响应；密集/长序列仍满足5秒接口门槛；纳入分析的关键窗口100%具备逐敌/墙/炮/角色/命令与连续性信息，无理由缺失明确标unknown；能复算至少一个完整夜晚的泄漏与资本链。若平台没有damage事件，成功只指关联与候选原因分离，不承诺精确归因率100%。
- **Failure interpretation**：字段缺失或日志截断意味着证据方案不足；行为差异/超时意味着观测侵入；仍无法区分攻击目标则需要平台事件/更窄控制场景，不能据猜测改策略。

### E2. 等墙数量/等级预算的布局对照

- **Hypothesis**：把同等墙资源放到观测到的进攻方向/入口，可以减少突破时间窗；“最短工人路径选墙”可能在优化施工而非防守。
- **Evidence**：G24西侧五墙、东侧开放；G21真实内圈敌人；G18/G24相同benchmark却不同损伤。
- **Single main variable**：墙坐标集合/选址优先级。
- **Control variables**：墙数及各等级/HP、三炮类型/等级/位置、角色夜初状态、目标选择、波次、gold预算。冻结夜初对照先隔离战斗几何；完整白天试验另报告因布局改变产生的actor-turn成本。
- **Required code changes**：下一阶段可选择的墙位置政策及可控场景加载/分析支持；不改wall目标数量或容量公式，不同时优化scorer。
- **Metrics**：首次内圈突破、近station HP-turn、墙接触/阻滞时间、station损失、炮手损失、实际建造交付率和路程。
- **Success criteria**：预先配对场景中生存不退化，泄漏暴露和station损失一致改善；完整白天能在原资源/时间约束下交付，否则只能确认几何效用，不能上线。
- **Failure interpretation**：墙外即可攻击、路径避让、火力不足或施工过贵可能让布局无净收益；不能由失败推出“再多加墙”。

### E3. 只替换一座L1炮的类型

- **Hypothesis**：两rocket加一座持续开火炮，可能以较短射程换取关键冷却窗口的响应能力。
- **Evidence**：G24首夜410HP损失落在全炮冷却窗口；规则gatling/railgun无冷却，但Round6没有组合对照。
- **Single main variable**：指定同一位置的一座L1 rocket → L1 railgun；其余两炮不动。gatling留作未来独立实验，本轮不并入第二类型变量。
- **Control variables**：建造顺序与25G成本、炮位、其他炮等级/升级对象、墙、角色夜初位置/HP、scorer、波次、deadline。固定被替换炮为未升级槽，避免升级对象随ID改变。
- **Required code changes**：下一阶段可配置单槽类型、保持同槽建造/升级身份及实验日志；不同时改target scorer。先核对既有railgun弹道实现与平台结果。
- **Metrics**：在射程内的实际可射窗口、冷却期响应、有效伤害与及时击杀、共线余能利用、失去的远程/AoE伤害、station损伤与存活。
- **Success criteria**：等预算配对下survival不退化，临近基地泄漏/损伤改善，并且损失的远程AoE不产生更大后续风险。
- **Failure interpretation**：可能是L1射程/单目标输出不足或现有scorer不适配；不能宣称所有混编无效，也不能在本实验内顺便改scorer补救。

### E4. 保持布局武器不变，仅替换夜间目标评价

- **Hypothesis**：用第6节的及时击杀/未来基地损伤评价，能比加权即时伤害减少威胁存活时间。
- **Evidence**：当前权重不含攻击力、ETA、击杀时限，且以角色×3覆盖station×2；已有共享remaining但无联合时序目标。
- **Single main variable**：夜间候选动作评分/组合选择目标。
- **Control variables**：同一夜初资产、炮位、三rocket等级、控制员匹配/站位、heal行为、金钱、白天策略、波次。控制员换岗不在本实验内修改。
- **Required code changes**：下一阶段可切换的旁路scorer及有界联合候选评估；保留原合法性校验、弹道和damage估值，日志标模型假设。
- **Metrics**：临近station敌人TTK、致死前未处理威胁数、overkill、预计与实际损失误差、station生存、有效kill/score、决策耗时。
- **Success criteria**：在标注的关键威胁场景及时处理且配对整夜生存不退化、漏防下降，计算仍在既定预算内；攻击目标/伤害归因未知场景必须保留不确定结论。
- **Failure interpretation**：ETA或攻击目标模型错误、火力不足、控制员不可用或原scorer已足够；不把“分数函数更复杂”作为收益证明。

### E5. 只约束缺口筹资任务的owner能力

- **Hypothesis**：资金未足且无可卖库存时，不让无法筹资的先锋成为FUNDING owner，可以减少空转并改善资金闭合。
- **Evidence**：G22 R162～167六轮先锋FUNDING空转，另一个持可卖库存50的worker被墙服务占用；当前worker_income仅worker。
- **Single main variable**：FUNDING阶段的actor能力资格门禁。
- **Control variables**：goal优先级、金额与reservation、墙/炮目标、deadline、正常采矿ROI、任务优先级、已足资/持券先锋配送权限均不变。释放NO_ACTOR预留不是本实验变量。
- **Required code changes**：下一阶段分配时增加FUNDING能力判断、明确无owner原因及回归场景；不做广义scheduler重写。
- **Metrics**：无能力FUNDING actor-turn、资金缺口闭合时间、目标交付率、worker经济/墙服务变化、下一夜资产与实际station损失。
- **Success criteria**：对应观测中先锋无能力FUNDING归零，已有持券/足资配送和任务契约不变；可闭合场景兑现更早且等条件生存不退化。若只是把FUNDING改成NO_ACTOR而无新增有效动作，只算诊断改善，不算战略成功。
- **Failure interpretation**：真正瓶颈可能在高优先级墙任务抢人或资金预留；据证据再提出下一次单变量实验，不能把两处一起修完后归因本项。

## 9. 唯一优先建议：V2.4 Phase 1

**推荐 E1：建立策略不变的因果可观测基线。**

原因不是缺少可以改的点，而是已经有多条同时成立的失败路径：几何缺口、范围内存活敌人、全炮冷却、炮手失效、资金/能力分配不闭合。现有日志能证明它们发生，却不能测出它们对station损伤的相对贡献，也不能判断先换墙、换枪、换靶还是改分工收益最大。直接从这些现象挑一个修，仍会延续V2.3“资产指标改善即认为防御改善”的验证方式。

Phase 1的具体交付边界是E1规定的白名单逐敌/资本链观测、可复算的夜战报告与响应等价/性能证据。先复用现有逐回合cooldown、邻接、墙HP，补最少但能关联因果的字段；平台不给的target/damage source继续unknown。取得完整夜战证据后，才从E2～E5中选择下一项行为实验。**Phase 1不包含新武器组合、目标选择、墙数/HP参数、deadline、资金策略或上述bug修复。**

阶段结束验收以E1指标为准，不能以比分偶然变好验收“观测patch”。本轮仅完成审计文档并停止，不继续实施Phase 1。
