# Self/4 日志分析与修复

## 证据与根因

分析对象为 log/Self/4.log 和 log/Official Demo/teamB.log，结合当前实现及 AI Spec 主规格。两份日志是不同场次/阵营，不能直接比较胜率。Self4 连续记录 R1–97，已观测动作反馈均为 true；合法不代表经济有效、答案正确或获胜。

| 瓶颈 | 日志事实 | 原因及修复 |
|---|---|---|
| 任务无收入 | 五次提交均失败；两题到 R24/R43 出现错误；首题 R18、第二题 R37–39 命令被四次上限拒绝 | 自设上限不符合实际探索需要；改为截止余量门禁，自动寻找题目和接口文档，保留材料和 skill |
| 运输低效 | move 127、collect 18、sell 4；工人携带仅四矿长途送货，R39 后金币一直 62 | 固定小批量、目标重选消耗移动；逐矿点评估采集送货收益，保持有效目标，远途扩大批量 |
| 缺少火力成长 | 三种武器各一座，至最后仍全部 L1；buy/use 都为零 | 改善变现，默认三火箭并优先升级，采购预算完整往返、买用及回防余量 |

Self4 火箭在 R75、79、83、87、91、95 开火，符合冷却节奏；电磁炮 R79–97、加特林 R83–97 持续参与，三角色存活至 R97。因此当前不是整夜无人操炮的问题。R90 基地 705 血；日志结束不能确认为死亡，全球机器人数量减少不能全部算作己方击杀。

Demo 在 R23/R43 完成两题，分别获得 80 金币、86/85 分；R70 金币 160、分数 171。第一题含自动寻找任务文件和接口文档，加上四次 LLM 命令，总探索超过四次。其 R117 基地也仅 40 血，不能作为强防御标准。本次没有复制答案或固定接口端口。

## 规格、实现与测试

- 主规格 §10/12 允许三武器任意搭配；§17 火箭 L1 射程 10、范围伤害、冷却 3，支持面向机器人群选择三火箭，但不证明最优。
- §23 升级价格及邻接使用约束继续由合法性校验保证；DefensePlanner 增加往返与入夜预算，正常优先火箭，危急基地例外。
- §35 规定命令 15 秒、输出 64KB、下一回合反馈，没有四命令限制。TaskPlanner 按截止门禁；task_discovery_command 只交给比赛沙盒执行，搜索有目录/深度/时间上限，最终 JSON UTF-8 限 48KB。超时或缺文件后继续普通解题。
- EconomyPlanner 和 GameMemory.worker_mines 实现逐矿点评分、目标保持及距离批量。验证见 tests/test_self4.py、test_strategy_regressions.py 和既有动作/任务/防御测试。

## 量化验证及边界

tools/replay_day.py 读取 Self4 首次地图和角色，结算 70 个日间回合的移动、采集、销售、建造、买用。每矿点 10 库存，无刷新、任务或战斗；这是对比假设，不是比赛规则。

| 相同模型 | 修改前 HEAD | 修改后 |
|---|---:|---:|
| 售矿收入 | 67 | 115 |
| 移动次数 | 110 | 94 |
| 采集次数 | 19 | 27 |
| 买/用次数 | 0/0 | 1/1 |
| 防御 | 三种武器各 L1 | 火箭 L2、L1、L1 |
| 剩余金币 | 67 | 15 |

收入约增加 72%，少移动 16 次，并在模型中完成一次升级。旧版模型收入 67 与实际日志 62 不同，不能混用。合成远距离 3×3 机器人群测试也验证三火箭预估单轮伤害至少为混搭两倍，仅限该场景，不等于真实夜战效果。

复现：`.venv\Scripts\python.exe -B tools/replay_day.py log/Self/4.log`，通过 `--source <旧版main3.py>` 对比。本次旧版保存在本机忽略文件 .venv/baseline_main3.py。Windows/WSL 完整 120 项均通过；独立审查发现的搜索额度和 JSON 转义膨胀均已修复。
